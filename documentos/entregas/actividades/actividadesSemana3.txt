4. Implementar StreamingResponseBody en un Rest

1. El Problema

Si una API necesita devolver miles o millones de registros (ejemplo: 50,000 o 1,000,000), Spring Boot por defecto:

Carga todos los registros en memoria.

Serializa todo el JSON.

Entrega el resultado completo al cliente al final.

Esto genera tiempos de espera largos (30 segundos, 1 minuto o más) → mala experiencia para el usuario.

2. La Solución: Streaming de Respuestas

En vez de esperar a que todos los datos estén listos, la API:

Va enviando bloques de datos (chunks) conforme se procesan.

El cliente empieza a recibir datos de inmediato, sin esperar al resultado completo.

Solución: StreamingResponseBody en Spring MVC

Usando el tipo StreamingResponseBody en el controlador.

Paso a paso:

Cambiar el tipo de respuesta a streaming (text/event-stream).

Iterar los registros.

Convertir cada registro a JSON.

Escribirlos al OutputStream y “flushear” para enviarlos al cliente.

👉 Ejemplo de uso:

Descargar un PDF/CSV grande.

Mostrar progreso de tareas largas.

Enviar logs en vivo.

Limitación: cada request mantiene ocupado un hilo de servlet. Escala mal si hay más de ~10,000 clientes concurrentes.
