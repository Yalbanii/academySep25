🔄 Visualización de Threads en Java - Evolución del Concepto

Versión 0: Thread.sleep() básico

Código clave:
Thread.sleep(5000); // El thread actual duerme 5 segundos

Diagrama de Estados del Thread

Main Thread
RUNNING
SLEEPING (5s)
RUNNING

🔑 Puntos Clave:

  • Thread.sleep() hace que el thread actual se detenga temporalmente
  • NO libera ningún monitor/lock
  • El thread mantiene todos sus recursos bloqueados
  • Útil para pausas simples sin sincronización
  • Puede ser interrumpido con InterruptedException

Versión 1: wait() sin sincronización ❌

Código problemático:
wait(5000); // ❌ IllegalMonitorStateException!

Diagrama de Error

Main Thread
RUNNING
❌ EXCEPTION!
⚠️ IllegalMonitorStateException: El thread no posee el monitor del objeto

🔑 Lección Importante:

  • wait() SIEMPRE requiere sincronización
  • Debe llamarse dentro de un bloque synchronized
  • El thread debe poseer el monitor del objeto
  • Sin sincronización = IllegalMonitorStateException

Versión 2: synchronized + wait() ✅

Código correcto:
synchronized void dormir() {
  wait(5000); // ✅ Ahora sí funciona
}
Monitor del Objeto Pato
Main Thread
RUNNING
WAITING (5s)
RUNNING
📌 Monitor: Adquirido → Liberado durante wait() → Re-adquirido

🔑 Diferencias clave wait() vs sleep():

  • wait() LIBERA el monitor → otros threads pueden entrar
  • sleep() MANTIENE el monitor → bloquea a otros threads
  • wait() permite sincronización cooperativa
  • wait() puede ser despertado con notify()/notifyAll()

Versión 3: Monitor Externo

Sincronización con objeto externo:
synchronized (obj) {
  obj.wait(5000);
}

🔑 Ventajas del monitor externo:

  • Permite sincronización entre objetos diferentes
  • Mayor flexibilidad en el diseño
  • Múltiples objetos pueden compartir el mismo monitor
  • Útil para coordinación compleja entre threads

🔑 Comportamiento con múltiples threads:

  • Orden de ejecución no determinista
  • Posible concurrencia real

Versión 7: Combinación wait() + sleep()

Patrón avanzado:

  obj.wait(5000); // Primero espera y libera
  Thread.sleep(5000); // Luego duerme y bloquea

🔑 Patrón híbrido:

  • Primera fase (wait): Todos esperan simultáneamente
  • Segunda fase (sleep): Ejecución secuencial con monitor
  • Útil para operaciones que requieren exclusión mutua después de esperar
  • Combina cooperación y exclusión

🎯 Decisiones de Diseño Clave:

  • ¿Necesitas sincronización? → No: usa sleep() | Sí: usa wait()
  • ¿Múltiples threads deben esperar simultáneamente? → usa wait()
  • ¿Necesitas mantener exclusividad durante la pausa? → usa sleep()
  • ¿Necesitas poder interrumpir la espera? → Ambos soportan interrupciones
  • ¿Necesitas notify/notifyAll? → Solo funciona con wait()

✅ Mejores Prácticas:

  • Siempre maneja InterruptedException apropiadamente
  • Documenta claramente por qué usas wait() vs sleep()
  • Considera usar java.util.concurrent para casos complejos
  • Evita esperas indefinidas - usa timeouts
  • Prueba exhaustivamente el comportamiento multi-thread
